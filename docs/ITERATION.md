# DollHouse 持续迭代记录

目标：让玩家乐于住在这座小屋里，逐步达到可正式发行的完整度。保持原版像素小人、统一的温暖家具配色、一个昼夜一个月的纪年；不以签到、限时心愿或任务堆积制造压力。

## 2026-11-13 · 留一份晚饭，完善人物细节

- 做饭真正完成后，愿意照顾室友的人可以留一份饭给晚归住户；从厨房端到可达的餐桌后，才出现盖好的饭、便签与小灯。做饭者主动让开，不和吃饭的人挤在一起。
- 指定的住户回来后实际寻路、端碗吃饭；不额外扣钱，按实际吃掉的份量恢复状态。全部吃完才增加关系、写入受助者记忆、相册和月报候选。
- 下一个昼夜之后，有空且愿意交流的双方会面对面提起便签、说声谢谢。对话被打断不算完成；未解的感情心结不会被自动修复。
- 每位做饭者每游戏月最多留一次，同时最多两份待吃。夜班跨月可用。访客、去邻居家做客、饱腹住户和无法到达餐桌的人不被硬拉入剧情。
- 保存半份饭、待送饭、准备次数与道谢进度；恢复后重新寻路，不重新付款、生成整份饭或重复获得回忆。搬家、拆桌、到期会清理；没有期限任务和失败惩罚。
- 人物保留原版 12×20 比例与正面/背面画法。侧面补耳朵、镜片反光、衣领、柔和下巴折角；修整双丸子和马尾轮廓，加入端碗、舀饭、说话手势及疲惫神态。
- 衣橱新增四种脸部细节，默认仍是原版小脸；新住户可自然生成。人物截图和套装图册均使用实际游戏绘制函数更新。

验证：88 项 Node 测试通过，包括完整留饭流程、实际寻路、吃到一半保存恢复、道谢被打断、跨月夜班、频率限制、拆桌/搬走/关系恶化边界。原有四位住户正面/背面的 160 个完整动作帧保持一致，侧面是本轮明确打磨的内容。新脸部细节、端碗各朝向和睡觉姿态均验证可见性与边界。

`late-supper-story.png` 来自游戏 Canvas 客厅局部，`late-supper.png` 是完整游戏帧，`resident-details.png` 直接调用人物绘制函数；可用 `tests/render-home-care.cjs` 重制。实际渲染发现并修复了做饭者在桌前遮挡吃饭者的问题。当前浏览器策略限制仍在，不将这些渲染与 DOM 模型检查当作手机实机验收。

## 2026-11-13 · 生活衣橱

- 在原版像素比例上新增 9 款发型、8 款上衣、3 款下装、6 款头饰、3 款随身配饰与 3 款鞋型；旧色号只追加，不挪动。
- 12 套生活穿搭提供协调配色；一键换装保留肤色和头发，随机新人也使用同一套配色库。
- 衣橱默认展示带真实像素预览的搭配卡和发型；人物设定单独一页。四个方向、四种动作可试穿；支持逐位住户还原本次穿搭。
- 围裙口袋、雨衣后领、背包肩带与包体按方向绘制。头饰与随身物件独立，睡觉/泡澡只画头时不会出现背包。
- 未覆盖开局形象或用户已有造型。新服饰跟随存档保存；相册保留拍照当时的旧穿搭。

验证：75 项 Node 子测试通过。四位开局住户共 384 个方向/动作帧与修改前逐像素一致（独立整数栅格回归及原生 Canvas 双重核对）；全部发型 × 头饰 × 四方向共 840 张头像均在画布内；验证新款可见、换装按钮、逐人还原、存档和相册。`wardrobe-collection.png` 直接调用游戏绘制函数生成，可运行 `tests/render-wardrobe.cjs` 重制，需要可选的 `@napi-rs/canvas`。

本轮沿用前述浏览器环境限制，未声称完成真实浏览器、移动端触摸验收。

## 2026-11-13 · 小屋时光

这一轮补上「愿望 → 玩家邀约 → 实际共同活动 → 关系和记忆 → 可收藏回忆」的完整过程。

- 九种性格各有自己的小心愿；同时最多两个未完成心愿，没有过期惩罚。
- 家庭晚饭、围坐讲故事、小小音乐会。选择 2–4 位住户；分别寻路、占据不同位置，优先前排避免遮挡，轮流对白并面向听众。
- 不邀请即将上班、睡觉或正在其他专属活动中的住户；有未解心结的两人不会被强行撮合。钱不够的住户也能吃家庭饭。
- 未到场、活动取消、家具移走不会凭空产生回忆或奖励；读档重新集合，饭钱只付一次。换家具布置会正常中断活动。
- 长期相册最多 120 条，最多珍藏 60 条；保留当期人物外观，可导出真实游戏绘制的纪念卡。
- JSON 备份下载、校验、导入预览、恢复前备份、撤销导入；导入后的月初快照与原时间线分开，撤销时还原。
- 阅读手记、备份预览时暂停时间；CSS 与脚本都带内容版本，避免发布后缓存旧界面。

验证：68 项 Node 测试；三类活动、四人集合、九种性格、核心 UI 按钮的 DOM 模型检查、连续五个月自然模拟、存档往返与失败处理。`home-time.png` 是实际游戏 Canvas 帧，`home-memory.png` 是游戏导出函数的输出，不是概念效果图。

环境限制：本地 HTTP 服务监听被拒绝，浏览器策略拒绝 file URL；未绕过限制。因此本轮不声称完成浏览器视觉、手机触摸或文件下载的端到端验收。

## 下一轮优先顺序

1. 在可用浏览器环境中做完整试玩：375/390px 手机、平板、桌面；核对菜单高度、键盘焦点、活动状态条、触摸拖拽、文件下载/导入和后台回来。修复实际发现的问题后再扩展内容。
2. 让回忆继续影响日常对白。住户能提起具体一起做过的事，隔几个月偶尔续约；避免每次见面重复同一句话。
3. 留饭已完成；继续加强物品与生活联系：可布置的纪念照片、手作物的来历、完成作品后的赠送；只在前后因果完整时添加。
4. 梳理首小时体验、长期经济和事件频率。保留自由生活，不添加打卡任务。

## 正式发行前仍需完成

- 真实设备和浏览器的长时间试玩、存储空间不足与恢复体验、移动端性能和可访问性验收。
- 调整经济与关系变化的长期节奏，扩大对白池并控制重复频率。
- 明确目标商店与打包形式，准备产品介绍、操作帮助、更新方式和反馈入口。
- 由项目所有者确认发布许可、素材权属与商店要求。仓库目前没有因此自动新增开源许可。

每轮读取此记录和实际 git 状态，优先完成一项可观察、可测试的体验改进，更新证据再提交发布。不能用「代码已合并」代替线上部署验证，也不能用 Canvas 渲染代替实机试玩。
